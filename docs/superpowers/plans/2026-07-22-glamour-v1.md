# Glamour v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build v1 of Glamour — an AI-native format + runtime for interactive animated canvases (vector + text), plus the CLI / MCP / skill adapters and a Studio playground.

**Architecture:** One headless **core** library owns the format (validate / applyOps / headless render) and the environment-agnostic scene+machine builder. A browser **player** reuses core's builder to play a `.glam` live. Thin adapters (**CLI**, **MCP**, **skill**) wrap core; a **Studio** web app wraps core+player. Approach A — compose Konva (render + hit-test) and XState (statechart) under our own format. Spine spike-proven 6/6 (see `docs/superpowers/spikes/`).

**Tech Stack:** TypeScript, npm workspaces monorepo, Konva 9, XState 5, node-canvas (headless render), Vitest (tests), tsup (lib builds), Vite + React (Studio), `@modelcontextprotocol/sdk` (MCP).

### Task A2: Semantic validation

**Files:** Create `src/validate.ts`; Test `test/validate.test.ts`
**Consumes:** `parseDoc`, types.
**Produces:** `export function validate(doc: unknown): { ok: boolean; errors: string[] }` — runs `parseDoc` first, then semantic checks:
1. Node ids unique.
2. Every `bind.node` exists; `bind.prop` is a known animatable prop of that node type.
3. `machine.initial` exists in `states`.
4. Every `state.on` target state exists.
5. Every `state.on` key is `"<nodeId>.<event>"` where nodeId exists and event ∈ **{click, hover, leave}** (v1 wired set; `tap`/`press` deferred to v2 — reject them so validate never green-lights an event the player won't fire) OR an input-condition string `"<input> <op> <value>"` with `<op>` ∈ {`<`,`>`,`<=`,`>=`,`==`,`!=`} and `<input>` an existing input key.
6. Every `state.set` key is `"<nodeId>.<prop>"` with nodeId existing and prop animatable.

- [ ] **Step 1 — failing tests** covering: unknown bind node → error; machine initial not in states → error; `on` referencing missing node → error; `set` targeting missing prop → error; a fully valid doc → `ok:true, errors:[]`.

### Task A3: Expression evaluator

**Files:** Create `src/expr.ts`; Test `test/expr.test.ts`
**Produces:**
```ts
export function evalExpr(expr: string, scope: Record<string, number>): number;
// evaluates a bind condition like "progress > 0.5" or "mood == 1" to a boolean.
// Used by both validate (A2 rule 5, syntax) and the player's XState guards (B1).
export function evalCondition(cond: string, inputs: Record<string, number | string>): boolean;
```
- `evalExpr` supports: number literals, identifiers (from scope), `+ - * /`, parentheses, and functions `lerp(a,b,t)`, `clamp(x,lo,hi)`, `min`, `max`, `abs`. No arbitrary JS — parse to an AST (`expr-eval` lib pinned, functions whitelisted) and evaluate. Unknown identifier → throws a descriptive error caught by caller.
- `evalCondition` parses `"<input> <op> <value>"` (ops `< > <= >= == !=`), reads `<input>` from `inputs`, compares against the literal (`<value>` may be a number or a bare string), returns boolean. Malformed condition → throws.
- [ ] **Step 1 — failing tests**:
```ts
test('lerp + identifiers', () => {
  expect(evalExpr('lerp(20,220,progress)', { progress: 0.5 })).toBe(120);
});
test('rejects unknown identifier', () => {
  expect(() => evalExpr('foo + 1', {})).toThrow();
});
test('evalCondition numeric compare', () => {
  expect(evalCondition('progress > 0.5', { progress: 0.7 })).toBe(true);
  expect(evalCondition('progress > 0.5', { progress: 0.2 })).toBe(false);
});
test('evalCondition string equality', () => {
  expect(evalCondition('mood == happy', { mood: 'happy' })).toBe(true);
});
```
- [ ] **Step 2** FAIL → **Step 3** implement (recommend `expr-eval` pinned, whitelisting functions) → **Step 4** PASS → **Step 5** commit `feat(core): safe expression evaluator`.

## Click on a MOVING node — PASS
- Tested:   Attempted direct click at live-read coordinates first — missed (log unchanged), because the crab moves between the coordinate read and the mouse event dispatch (async round-trip lag > single-frame travel distance at ~2.8s/full-width speed). Retried by pausing the animation (`window.player.pause()`) — an observation-only runtime toggle, not a code change — re-reading `crabA-body`'s absolute position, clicking exactly there, then resuming (`window.player.play()`).
- Expected: Clicking the crab body hits its Konva hit region (r=26 circle) and fires the node's `emit`.
- Actual:   First live-timed attempt missed (`#log` stayed "host is listening..."). Pause-then-click attempt hit: `#log` → `host heard: picked crab-a (node crabA-body) — React would score this`.
- Evidence: <repo>/docs/superpowers/qc/evidence/v0.1/crab-click-log.png
- Note:     Flagging honestly per instructions — the crab IS too fast/small (r=26 hit radius, ~490px travel in 2.8s) to hit reliably with a live coordinate read + separate mouse dispatch given IPC lag between playwright-cli commands. Motion and the click→host-log wiring both work; the "reliably click a live-moving target purely by screenshot-and-guess" path is fragile by nature of canvas rendering + command latency, not a product defect.

## Page 2 — orb.html (free `wander` + node `groups` + host `player.send` states)

## Free wander in idle — PASS
- Tested:   Screenshot at t=0, wait ~1s, screenshot again (visual); also sampled the `face` group's Konva `x()/y()` four times at ~0.8s intervals via `window.P.__byId['face']`.
- Expected: Face group (`eyeL`, `eyeR`, `mouth`, all children of `group: "face"` anchored at x:180,y:190) drifts slightly and continuously while state is idle.
- Actual:   Numeric samples: `(187.07,187.97)` → `(187.60,190.08)` → `(181.00,190.08)` → `(193.69,198.02)` — non-monotonic small drift around the 180/190 anchor, i.e. genuine wander motion, not a frozen frame. (Visual screenshots at 1s apart look similar at this drift magnitude — the numeric Konva read is the load-bearing evidence here, screenshots are supporting.)
- Evidence: <repo>/docs/superpowers/qc/evidence/v0.1/orb-wander-1.png, <repo>/docs/superpowers/qc/evidence/v0.1/orb-wander-2.png, <repo>/docs/superpowers/qc/evidence/v0.1/orb-idle-state.png (`state: idle` visible)

## Host-commanded states via player.send — PASS (all 4 states)
- Tested:   Clicked each button (`✓ Check`, `★ Star`, `♥ Heart`, `← Idle`) in the DoD's sequence, reading `#st` (`state: <x>`) after each and screenshotting the orb.
- Expected: Check → orb green + checkmark, face hidden, `state: checked`. Star → gold + star/diamond glyph, face hidden, `state: star`. Heart → red + heart glyph, face hidden, `state: heart`. Idle → back to blue + wandering face, `state: idle`.
- Actual:
  - Check: orb turned green (`#2ecc71`-ish), white checkmark glyph shown, face hidden, `#st` = `state: checked`. Evidence: crab-checked screenshot below.
  - Star: orb turned gold, white rotated-square ("diamond") glyph shown (the `.glam` doc defines the star node as a 45°-rotated square, not a 5-point star — matches spec as authored), face hidden, `#st` = `state: star`.
  - Heart: orb turned red, white heart glyph (two circles + rotated square) shown, face hidden, `#st` = `state: heart`.
  - Idle: orb back to blue, face visible again (eyes + mouth), `#st` = `state: idle`.
- Evidence: <repo>/docs/superpowers/qc/evidence/v0.1/orb-checked.png, <repo>/docs/superpowers/qc/evidence/v0.1/orb-star.png, <repo>/docs/superpowers/qc/evidence/v0.1/orb-heart.png, <repo>/docs/superpowers/qc/evidence/v0.1/orb-back-idle.png

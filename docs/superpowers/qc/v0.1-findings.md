## Code review (Gawain) — CHANGES REQUESTED
- **[CRITICAL C1] Live wander = random jitter, not drift.** `loop.ts:59-63` passes `Math.random` to
  `Wander`, but `motion.ts:104-109` re-draws EVERY segment target from `rng()` on each `valueAt` call —
  only stable if rng is a pure function of draw-index. With `Math.random`, endpoints change every frame →
  face teleports ~60×/s instead of easing over `stepMs`. Breaks the orb proof. Untested (RunLoop test
  covers loops only; core wander tests used scripted rng that masked it).
  **Fix:** `Wander` samples each segment's target ONCE and caches by segment index (stateful controller,
  instantiated once). Fixes C1 + I1. Add a real test: many `valueAt` calls within one segment → stable
  target; and a RunLoop wander smooth-drift test.
- **[IMPORTANT I1] `Wander.valueAt` is O(elapsed/stepMs) per frame, unbounded** — re-samples all n targets
  each call; cost grows with runtime. Same memoization fix.
- **[M5 cheap] `@EVENT` named `INPUT` collides** with input-condition transitions (machine.ts overwrites
  `on.INPUT`). Reserve `INPUT` in validate (reject `@INPUT`).
- **[M3 minor] pointer-event set triplicated** (validate.ts:18 / machine.ts:5 / player.ts:35) — single-source it.
- **[M4 minor] `setInput` clobbers a live loop/wander value for one frame** if bind+loop on same node/prop.
  validate guard or doc note.
- **[M2 accept] `canvas.bg` painted rect** = intended v1 fix; only a v0 snapshot-diff risk (we have none). No action.
- **Confirmed correct:** loopValueAt math (period/peak/wrap/ms<=0 guard); run-loop lifecycle (pause/destroy
  truly stop; pause/resume no time-jump — verified against Konva Animation); host API (send/on/unsub/emit for
  grouped children); groups + resting-frame seeding; backward-compat (v0 → no motion, only M2 shared change);
